# Конвертер ТТ → формы СУО (2R / R3 / 4R)

Автономное HTML-приложение (работает офлайн, без сервера): читает консолидированную
трансформационную таблицу (ТТ, файл `T_-KMTF-ГГГГ.ММ_CONSO_*.xlsm`), заполняет формы ввода
системы управления рисками Фонда:

* **2R** — страновой риск,
* **R3** — отчёт о величине валютного риска,
* **4R** — отчёт по процентным разрывам в разрезе валют,

хранит историю периодов в браузере, строит аналитику (динамика ОВП, структура по валютам,
страновые позиции, процентный разрыв, изменения к прошлому периоду, автокомментарии) и
выгружает заполненную форму в Excel на основе оригинального шаблона (включая казахские листы).

## Запуск

Откройте `index.html` в современном браузере (Chrome, Edge, Firefox). Интернет не нужен —
библиотеки лежат в `vendor/`, шаблон формы встроен в `js/template.js`.

## Порядок работы

1. **Загрузка** — перетащите файл ТТ. Берётся лист `TT`, колонка «Итого» (консолидированные
   данные после корректировок; в настройках можно переключить на «Package sum»).
   Период (`Q3 2026`) и компания определяются по титульному листу; укажите курс USD/KZT
   на отчётную дату — он нужен для порога 1 млн долл. США по форме R3.
2. **R3 / 2R / 4R** — предпросмотр заполненных форм. Любую суммовую ячейку можно поправить
   прямо в таблице (Enter — сохранить, Esc — отмена); правки подсвечиваются и попадают в выгрузку.
   В 2R можно добавить страну из справочника формы.
3. **Контроль** — сверка каждой строки R3 со строкой баланса ТТ и журнал допущений маппинга.
4. **Сохранить период в историю** — запись хранится в `localStorage`; предыдущий период
   подставляется в графы «Прошлый период» / «Разница» всех трёх форм.
5. **Скачать форму СУО (Excel)** — файл `SUO_2R_R3_4R_<период>.xlsx` с заполненными листами
   `2R`, `R3`, `4R` и их казахскими копиями. Формулы шаблона (итоги, разницы, SUBTOTAL) сохраняются.
6. **Аналитика** — KPI, графики, таблица изменений и редактируемые автокомментарии
   (попадают в графы «Комментарии» форм).
7. **История** — список периодов, повторная выгрузка Excel/JSON, экспорт и импорт всей истории
   (для переноса между компьютерами).

## Правила маппинга (кратко)

Все суммы — тыс. тенге, как в ТТ и формах. Строки ТТ находятся по кодам счетов
(`AC sum AC-TT-5077`, `AC=A10501010000`…), валют (`CT=USD`) и раскрытий (`DC=DC47.001`), поэтому
маппинг не зависит от номеров строк. Полный перечень правил — в `js/mapping.js` (`R3_LINES`).

**R3 (валютный риск).** Каждая строка формы = сумма блоков «в разрезе валют» ТТ
(например, денежные средства = вклады `A10501010000` + текущие счета `AC-TT-5077` по валютам).
Валюты ТТ (RON, GEL и «в другой валюте») попадают в графу «Прочие». Статьи без валютного раскрытия
(ОС, запасы, НДС, налоги, резервы, ПФИ, аренда и т.п.) относятся в тенге, чтобы графа
«Все валюты» сходилась с балансом; каждое такое допущение пишется в журнал. Займы полученные и
долговые ЦБ: валютный разрез ТТ общий, делится между текущей и долгосрочной частью пропорционально
балансу. Чистая валютная позиция, отношение к капиталу — формулами в Excel. Порог: если
|ОВП| ≤ 1 млн USD, выгружается пустографка с причиной (режим переключается в настройках).

**2R (страновой риск).** Деньги и вклады разносятся по банкам из раскрытий ТТ
(«в разрезе банков»); страна банка определяется по названию (правила `COUNTRY_RULES`),
неопознанные банки — на страну по умолчанию с предупреждением (справочник банков — в настройках).
Займы выданные и финансовые активы — на страну по умолчанию (в ТТ нет разреза по странам).
Торговая ДЗ и авансы по умолчанию распределяются **пропорционально выручке по странам** из ТТ
(прокси-оценка, отключается в настройках). Гарантии и аккредитивы в ТТ отсутствуют — вводятся
вручную. Страновые лимиты и рейтинги (графы 10 и «Рейтинг страны») задаются в настройках;
потолок 50% СК (СТП КМТФ.033/.034) показывается справочно. В блок «за предыдущий отчётный
период» выгружаются 5 крупнейших стран прошлого периода и отклонения по ним.

**4R (процентные разрывы).** Обязательства раскладываются по срокам из таблицы «Риск
ликвидности» ТТ (`ZZ45010…` × `DC47.00x`), активы — по доступным срочным раскрытиям
(вклады: деньги на депозитах → «до 1 мес.», краткосрочные вклады → «3–12 мес.»,
долгосрочные → по DC47). В форму попадает только доля, чувствительная к ставке:
коэффициенты по категориям — в настройках (по умолчанию займы полученные = доля займов
с плавающей ставкой по ТТ, ПФИ и средства Правительства = 100%, остальное = 0).
Если доля чувствительных < 5% суммы активов и обязательств — выгружается пустографка с причиной.
Валовые суммы до коэффициентов видны в развороте под таблицей.

## Хранение данных

* `localStorage['suo.history.v1']` — периоды (значения форм, комментарии, правки, журнал).
* `localStorage['suo.settings.v1']` — настройки (курс, компания, подписи, коэффициенты,
  справочники банков/лимитов).
* Кнопки «Экспорт/импорт истории (JSON)» переносят всё между браузерами и компьютерами.

## Структура

```
suo-converter/
  index.html        интерфейс
  js/mapping.js     разбор ТТ и правила маппинга (чистая логика, тестируется в Node)
  js/app.js         интерфейс, история, аналитика, выгрузка Excel
  js/template.js    шаблон формы СУО (base64)
  vendor/           ExcelJS 4.4.0 (MIT), Chart.js 4.4.1 (MIT)
  tests/smoke.js    проверка маппинга на файле ТТ: node tests/smoke.js <путь к ТТ>
```

## Ограничения

* ТТ не содержит страновой разрез дебиторской задолженности, номиналы гарантий/аккредитивов
  и валюту обязательств по аренде — эти позиции требуют ручной проверки (журнал на вкладке
  «Контроль» перечисляет все допущения).
* Коды счетов соответствуют версии ТТ 1.01 (периметр KMTF). При изменении структуры ТТ
  строка формы, для которой не найдены коды, помечается в журнале, а контроль с балансом
  покажет расхождение.
